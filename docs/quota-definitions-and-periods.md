# Quota definitions and entitlement periods (COM.18)

The Entitlement owner implements the complete canonical quota semantic validator, immutable persistent profile/key ledger, receipt-safe publication, and current paid-period read source. `IQuotaDefinitionPort` and `IQuotaPeriodSource` are server composition contracts; neither a profile hash nor a period snapshot grants permission to perform business work. COM.07 must compose actual current Configuration, Workspace, Entitlement, recovery-generation and quota-budget guards in the accounting transaction.

## Canonical semantics and real sources

`entitlement.quota-definitions.v1` has exactly `definitions`, `definitionsVersion`, and `schemaVersion`. Definitions are sorted by unique actual resolver key; each has exactly `combination`, `key`, `mode`, and `unit`. The closed combinations are Sum/Max/PriorityReplace; units are bytes/microseconds/samples/count; modes are Gauge/EntitlementPeriod. Validation checks complete canonical UTF8 bytes, exact independently supplied resolver membership/combination, at most64 definitions and65536 bytes. Successful pure validation is not operator approval.

The publisher reopens the real Config owner's exact historical approved revision/document association and configured trusted publisher identity, reads the independent resolver definition source, and separately reopens the exact artifact tuple. It validates bytes, hash, length, realm kind and expected definitions before persistence. Config owns approval and signed subjects; Entitlement does not accept a caller approval flag or infer metadata from a quota name. Historical approval is necessary for retained materialization commands and is distinct from current purchase or new-work authorization.

The current resolver adapter consumes the actual injected `IEntitlementDefinitionSource.Current()` and real configured realm/recovery authority. It returns only that exact current definition version. An absent producer is Unavailable; unknown, future or historical versions are NotFound. The generated Configuration schema presently contains no independent full resolver key/combination/version set. A genuinely versioned approved resolver-definition source remains required for staging future definition versions; the current adapter does not manufacture a default registry or derive expectations from the candidate semantic profile.

## Persistent invariants and lifecycle

The append-only `entitlement_quota_definition_profile` stores exact canonical bytes and artifact provenance by realm/version. The indexed append-only `entitlement_quota_definition_key` retains each original unit/mode/combination and first version even when later profiles remove the key. A single named guarded batch checks existing meanings, inserts only absent key/profile rows, and writes the real platform command receipt and change archive. Concurrent differing versions cannot redefine a key or leave a partial profile. Old profile/key rows reject update and delete.

Commands use the immutable realm/revision/document/publisher binding and a seven-day receipt. Exact known replay returns the original stored profile without reopening a now-unavailable artifact/current resolver. Historical Config authority still must be available. A changed request cannot reuse the command; an expired known command is never executed again. Unknown responses reconcile the actual receipt before any bounded retry of the identical command. Unavailable reconciliation after an unknown write remains UnknownOutcome. Cancellation is checked after awaited reads and writes; cancellation after a genuine commit reports cancellation without claiming rollback, and exact replay recovers the committed result.

## Actual period provenance

New owned keyset plans retain real service-term realm/workspace/kind/period_ref, original start/end, authorized_at, signed selection_priority, created_at, and complete action identity/source/replacement/knowledge time. Existing resolver summary plans and snapshot canonical encoding remain unchanged. Reads require positive stored Entitlement revision and snapshot version, bound total term/action history to2000, and reread the exact revision/snapshot after pages. Three continuously changing read attempts refuse Unavailable. Current Config association is reopened after profile/store reads; a changed head or an elapsed/future snapshot refuses Stale.

Selection uses the exact official/selfHosted term-kind doctrine and the paid interval `[max(starts_at,authorized_at), effective_end)`, excludes grace and rows/actions not yet known, and truncates by actual recorded supersede/revoke actions. Highest pinned priority wins, with canonical term ID as a deterministic tie breaker. Negative priorities remain valid. The opaque `term:` SHA256 key binds a domain-separated length-prefixed tuple of realm, workspace, kind, original term ID/period_ref and original start/end. Actions do not rewrite period identity; A-to-B-to-A selection returns A's original key. Gauges receive no invented calendar period, and EntitlementPeriod admission without an eligible paid period is unavailable for new work. Old accepted reservation settlement remains COM.07's pinned-basis obligation.
