# Versioned resolver definitions (COM.20)

Entitlement owns the complete immutable capability, quota-combination and allowance definition artifact. Configuration owns approval and the current association. The full artifact is independent of the quota unit/mode artifact: Configuration validates it first, then validates unit descriptors against the resulting complete quota set. A candidate cannot define its own expected quota keys by repeating them in its unit artifact.

## Private artifact and authority

`entitlement.resolver-definitions.v1` is canonical UTF-8 JSON, at most 65,536 bytes, with at most 64 entries in each of the capability, quota and allowance arrays. The exact root properties are `allowances`, `capabilities`, `definitionsVersion`, `quotas`, `schemaVersion`, in that order. Arrays are sorted by unique ordinal key. Capability entries carry `featureGate` (null or an existing feature key), `key` and `requiresPaidTerm`; quota entries carry the exact `Sum`, `Max` or `PriorityReplace` combination and `key`; allowance entries carry `key`. Keys and the at-most-128-byte opaque definitions version use the existing COM.05 grammar. The validator rejects noncanonical bytes, unknown/duplicate properties, unsupported enum values, malformed UTF-8 and excess bounds. Validation alone confers no approval.

The neutral approved association names the realm, exact Config revision and document hash, signed document `official`/`selfHosted` realm kind, definitions version, and immutable artifact ID/profile/hash/verified length. The Config producer must reopen consumed, qualified, dual-approved immutable evidence and the exact signed artifact association. Its configured trusted materializer identity is the publisher; a proposer or approver alias cannot substitute for it. Artifact bytes reopen through a separate bounded copied-byte port, then Entitlement independently hashes and validates them. An absent authority or unmaterialized current association is a typed refusal, with no old-version/default registry fallback.

## Persistent publication and captured resolution

The append-only `entitlement_resolver_definition_profile` row is keyed by realm and definitions version. It retains the complete canonical profile and first accepted Config/document/publisher provenance. A later approved Config may reuse the exact same artifact under that version, recording its own stable-command receipt without changing the original row. Different semantics, artifact identity or realm kind under the same version refuse in the same atomic batch. Update and delete triggers preserve accepted history.

Publication uses the owning named plans and the existing platform commit executor, seven-day receipt and archive. It checks authorized exact identity before artifact I/O, reconciles the receipt before a bounded identical retry, and captures one commit instant for all attempts. An uncertain write followed by unavailable reconciliation remains unknown; cancellation after a real commit propagates without claiming rollback. Fresh creation requires the exact current association, reopened after artifact I/O and before each attempt. A superseded association can recover only an already accepted matching immutable profile. Receipt replay independently binds the reopened retained approval to the stored profile. These host observations do not prove an atomic current-head write guard; Configuration's successor-stage accepted-profile fence and the runtime guarded family remain required.

The production grant port selects `VersionedEntitlementService`, which captures one immutable current definition set asynchronously for each operation. It composes the existing COM.05 engine and the COM.16 prepared owner mutation; the pure resolver, snapshot encoding and single writer are unchanged. Synchronous `IEntitlementDefinitionSource` fixtures do not supply production grant authority. Reads reopen current Config and recovery authority before returning. Historical rebuild loads the exact persisted snapshot definitions version and its retained immutable profile, even after replacement.

`entitlement-definition-resolution.commit-current` contains the real current Platform recovery guard, the Config-owned current revision/document-hash guard with literal active state `2`, the positive persisted Entitlement revision (or verified absent revision `0`), the exact immutable profile tuple, and the original Entitlement records/snapshot/tail. Config issues its own opaque issuer/family/plan/workspace-scope capability after verifying actual consumed signed evidence; its evidence is immutable and the head is fenced in this same batch. The caller supplies no approval boolean, foreign descriptor, SQL or active-state argument. C82 rejects foreign issuers, other scopes and legacy unscoped capabilities. Platform authority comes from C75's actual required deployment capture and current recovery read. Missing Config or recovery participants fail closed.

Migration ordinal and immutable release profile allocation belong to the Cloud integration queue, after the actual accepted predecessor; the pending DDL is not a numbered production migration.
