# Sharp development-tool security update

GOV.22 addresses [GHSA-wq5f-xc86-pv6w](https://github.com/advisories/GHSA-wq5f-xc86-pv6w), published on 2026-10-06. The locked Miniflare development dependency used Sharp 0.35.4, whose Linux glibc builds contain the affected librsvg dependency. Sharp 0.35.5 supplies the upstream patch. Earlier green Cloud CI predates the advisory and does not establish current audit success.

The only package-manifest change is the exact nested override `miniflare` → `sharp` → `0.35.5`. Wrangler remains 4.143.1 and Miniflare remains 5.20260926.1-alpha. Updating Wrangler alone would not fix this advisory: the researched 4.147.0 closure also selects Sharp 0.35.4. Automatic audit repair would propose an unrelated Wrangler downgrade, so it is not an admitted solution.

The regenerated lock advances only the existing Sharp 0.35.4 platform packages to 0.35.5 and their existing libvips 1.3.3 packages to 1.3.4. It adds or removes no package entry. Each exact registry coordinate and integrity, including optional packages for other platforms, is admitted by the immutable GOV.22 dependency receipt. The licence expressions remain unchanged: Apache-2.0 for Sharp, LGPL-3.0-or-later for libvips, and the existing combined expressions for bundled native or WebAssembly packages. The patched Sharp package's complete Apache-2.0 licence is byte-identical to the predecessor (LF-normalized SHA256 `73ba74dfaa520b49a401b5d21459a8523a146f3b7518a833eea5efa85130bf68`). These dependencies remain build and development inputs; the update grants no permission to distribute them as product native capabilities.

The active release profile and artifact records advance through retained immutable successors because the application image profile binds the npm lock as a build input. The declared Worker source, emitted bundle bytes, package coordinates, exports, runtime image pins and full legal documents remain unchanged. Verification compares the actual generated Worker with the retained bundle identity; the normal candidate pipeline still builds and inspects the real Native AOT image. No production route, D1 schema, secret, data or `workers.dev` setting changes.

The mandatory high-severity npm audit, immutable dependency history, provenance and applicable source/build gates remain enabled. Component and build evidence are recorded on the task PR and ledger. A passing audit is evidence about the scanned package closure; it does not certify OS isolation, every platform's native runtime, or whole-system commercial acceptance. Production delivery is established separately by the normal main deployment receipt.
