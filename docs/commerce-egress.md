# Restricted commerce HTTPS transport

CLOUD.74 composes the accepted COM.01 HTTP adapter with the existing Cloudflare Container profile. It adds no public method, merchant credential, business authorization or payment policy. COM.03 constructs the real provider from approved configuration; COM.04 and COM.09 own durable event/mutation/reconciliation behavior. The public ingress, Container class identities, private proof storage/object handlers, routes and data are preserved. Global Container Internet, `workers.dev` and preview URLs remain disabled.

## Worker boundary

Vendor-aware implementation is confined to `worker/commerce-provider/egress.ts`. Both existing Container classes register only exact production/sandbox API hosts, alongside the proof class's existing two private hosts. There is no wildcard, catch-all handler, `allowedHosts`, direct Internet fallback, arbitrary destination parameter or redirect forwarding. The locked SDK registers per-host HTTP and HTTPS interception. Component tests execute its actual registry/configuration; unavailable platform interception calls are spies. This does not prove OS isolation.

The non-secret `COMMERCE_EGRESS` variable selects `production` or `sandbox` in the corresponding profile. Missing/disabled configuration does not enable host trust; an unrecognized configured mode refuses. The handler admits only its selected HTTPS hostname on 443, with no URL credentials/fragment, and the exact provider purposes used by COM.01: price/product and transaction/address reads, bounded transaction/subscription/adjustment/event listings, transaction creation, cancellation, scheduled-change update, refund adjustments and temporary customer portal creation. References/query keys are validated; duplicate/unknown queries fail closed. No GET body is forwarded.

Only validated bearer authentication, API version, JSON media type and accept headers are forwarded. Cookies, caller destination hints and unrelated headers are dropped. Declared and actual request bodies are bounded at 32 KiB and replies at 16 MiB. A 30 second budget covers upload, real fetch, provider reply and downstream consumption. Reads/mutations are never retried here. COM.01 retains bounded read retries; ambiguous mutations require reconciliation.

At most two exchanges hold buffered replies per Worker isolate. The permit lasts through downstream EOF/cancel/deadline; bounded chunks respect backpressure. No waiting queue accumulates. Capacity refusal is 429 with `Retry-After: 1` before upstream dispatch. Cancellation, timeout, overflow, redirect or network errors after dispatch are generic 502/504 failures. No credentials, request/reply bodies or arbitrary supplier diagnostics are logged or persisted. Raw financial bytes remain ephemeral transport input for the accepted allowlisted normalizer.

## Host trust and composition

Interception mounts the platform's ephemeral CA at `/etc/cloudflare/certs/cloudflare-containers-ca.crt`; it is runtime input, never baked into the image. [Cloudflare's outbound documentation](https://developers.cloudflare.com/containers/configuration/outbound-traffic/) and the locked SDK identify this mount/API.

`Infrastructure/CommerceHttpTransport.cs` creates fresh owned handlers with bounded public-CA snapshots, `CustomRootTrust`, ordinary hostname/chain/time verification, no validation callback, no system-trust mutation, and no proxy/cookies/redirects. Missing, malformed, non-CA, expired, oversized or private-key-containing authority input fails closed with generic configuration errors. Only this platform authority is trusted. Certificate downloads are disabled; this ephemeral root publishes no revocation service. A handler owns/disposes its certificate and socket handler. Recreate the provider on Container restart/ephemeral-CA replacement; no system-trust fallback exists.

The host registers keyed `Func<HttpMessageHandler>` named `commerce-provider-transport`. It serves no route and imports no Commerce business type. The lazy factory refuses unless `ARCFORGES_COMMERCE_EGRESS` is exactly `enabled`. The Container forwards that neutral flag only, never a merchant key. COM.03's module-owned registration resolves the delegate and passes its fresh handler to `BillingProviderFactory.Create`; the returned provider owns it. Approved provider environment, credentials, capabilities, region/currency and immutable pricing terms remain Configuration/Commerce responsibilities. Fresh provider reads never authorize configuration.
