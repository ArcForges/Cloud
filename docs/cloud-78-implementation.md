# Security lifetime predicates

CLOUD.78 compiles closed Identity lifetime annotations into the named guarded SQL statements. A request cannot supply SQL, a clock function, a table, a profile or a registration. The source role, family, table and complete column set must match the canonical compiler registry. Pending StepUp and deletion due profiles also name their exact allowed plans.

`securityExpiry=...` requires every deadline to be an integer and later than both the captured trusted server observation and SQLite's execution-time UTC millisecond ceiling, expressed as integer microseconds. Native access also checks absolute expiry; browser access checks idle and absolute expiry; refresh checks absolute expiry. Action proofs, pending challenges, native codes, browser flows, enrollment flows and persisted deletion cancellation each have an explicit profile. These annotations provide lifetime checks; proof, session, state, revision, ownership, operation, target and recovery authorization remain the owning participants' responsibilities.

`securityDue=grace_ends_at` is restricted to the persisted deletion begin/purge completion roles. It compares the integer saved deadline with SQLite's actual UTC millisecond floor. It accepts no captured clock parameter. A caller observation cannot prove that a purge deadline has arrived. Null clock results or deadlines refuse. The ceiling can refuse an expiry up to one millisecond early; the floor can allow a due transition up to one millisecond late. Neither converts a not-yet-due deadline into due or extends an expired lifetime.

SQLite obtains `now` from its VFS and keeps it consistent within one statement step; it does not promise one clock sample for the entire transaction. The compiler uses integer `strftime` seconds and millisecond digits, avoiding floating point timestamp rounding. See the [SQLite date/time specification](https://www.sqlite.org/lang_datefunc.html). A backward database clock cannot weaken an expiry's captured server lower bound. Due transitions deliberately use only the database floor and can wait until that clock reaches the saved deadline.

The same compiler emits immutable C# role metadata and the closed profile registry. C# validates role, family, profile, columns, plan restrictions and parameter shape before contribution dispatch. The shared manifest binds the actual generated SQL to the Worker dictionary. `ModuleFamilyPortFactory` copies nested metadata; it does not grant authority through these annotations. Existing generic `fresh`, lease and policy SQL remains unchanged.
